# EELForge v0.2 Bolt Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the Bolt React overhaul as EELForge `0.2.0` with six verified prompt modes, safe schema-1/2/3 migration, hardened multi-project persistence, tests/CI, and an offline single-file handoff.

**Architecture:** React components own presentation. Domain, migration, import/export, storage, filenames, templates, and six prompt compilers remain pure typed modules. Persistence uses one schema-3 workspace envelope with a persisted active project, strict import boundaries, ten snapshots per project, global oldest-first pruning, and a 3 MiB serialized budget.

**Tech Stack:** Node.js 22, React 18.3, TypeScript 5.6, Vite 6, Vitest 3, jsdom, Testing Library, GitHub Actions.

## Global Constraints

- Work only on `integration/bolt-v0.2-overhaul`; never update `main` during implementation.
- Release is exactly `0.2.0`; schema is exactly `3`.
- Modern sections: `@init`, `@slider`, `@block`, `@sample`.
- Legacy sections: `@init`, `@sample`.
- Generic EEL2 / EEL_VM has no predefined section contract.
- Defaults: stereo, 44.1/48 kHz, zero latency, mobile-balanced, Galaxy S10 and Galaxy S24 Ultra, smoothing and protection required.
- Architect forbids final code. Build/Repair/Refine/Optimize request one complete script. Review requests findings, not a rewrite.
- Import rejects arbitrary JSON and regenerates identity.
- Reset and restore preserve `id` and `createdAt`.
- Keep ten snapshots per project; prune oldest snapshots globally to fit 3 MiB; never truncate active content.
- Remove Compare. Exclude `.vite/`, `.eelforge_ref/`, caches, and generated directories.
- Portable artifact: `releases/EELForge-v0.2-Handoff.html`, offline and `file://` compatible.
