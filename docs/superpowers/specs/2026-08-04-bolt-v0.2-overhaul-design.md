# EELForge v0.2 Bolt Overhaul Integration Design

**Date:** 2026-08-04  
**Status:** Written specification awaiting final review  
**Target branch:** `integration/bolt-v0.2-overhaul`  
**Target release:** `0.2.0`

## Goal

Integrate the Bolt-exported React overhaul as EELForge v0.2 while preserving the current repository's verified RootlessJamesDSP contracts, deterministic prompt behavior, migration safety, automated testing, CI, documentation, and portable single-file policy.

All six prompt modes become active:

- Architect
- Build
- Repair
- Refine
- Optimize
- Review

Every mode remains a local prompt compiler. EELForge does not call an AI provider, execute EEL2, or claim a generated script is valid merely because a prompt was produced.

## Source authority

The Bolt export is authoritative for the React interface, component structure, dashboard, templates, multi-project workflow, six-mode workspace, and version-history concept.

The current GitHub `main` branch is authoritative for RootlessJamesDSP host contracts, Phase 2A prompt invariants, schema compatibility, testing and CI expectations, repository documentation, license, and portable-handoff policy.

When the two sources conflict, correctness and compatibility from `main` override the Bolt prototype. The Bolt interface should otherwise be preserved.

- React v0.2 application shell

## Excluded scope

- AI-provider calls
- EEL2 compiler or runtime integration
- Static-analysis claims
- Cloud sync, accounts, authentication, or telemetry
- Automatic version snapshots
- A visual prompt or script diff tool
- Broad dependency modernization

The Bolt `Compare` control is removed because its current implementation is placeholder text. A real comparison feature requires a separate design.

## Canonical architecture

The canonical source becomes React + TypeScript + Vite:

```text
src/
├── App.tsx
├── main.tsx
├── domain.ts
├── migrations.ts
├── store.ts
├── filename.ts
├── templates.ts
├── components/
├── hooks/
└── prompt/
```

Prompt modules remain pure functions of `ProjectState`. Components own presentation. Storage and migration remain independent from rendering.

The Bolt package lock is the dependency baseline for v0.2. Dependency upgrades are deferred so the UI overhaul and toolchain modernization are not mixed into one release.

## Schema 3

```ts
interface ProjectState {
  schemaVersion: 3;
  appVersion: '0.2.0';
  id: string;
  name: string;
  createdAt: string;
  updatedAt: string;
  activeStage: 'vision' | 'architect' | 'build' | 'iterate';
  promptMode: 'architect' | 'build' | 'repair' | 'refine' | 'optimize' | 'review';
  vision: VisionState;
  contract: ContractState;
  architectureReport: string;
  eel2Script: string;
  iterationNote: string;
  onboardingDismissed: boolean;
}
```

`schemaVersion` and `appVersion` are literal types.

Reset preserves `id` and `createdAt`, clears user content, restores defaults, and updates `updatedAt`. This prevents the Bolt prototype's reset behavior from changing the project ID and invalidating `activeId`.

## Host contracts

The official mapping is:

```ts
const hostSections = {
  'rjdsp-modern': ['@init', '@slider', '@block', '@sample'],
  'rjdsp-legacy': ['@init', '@sample'],
  'eel-vm-core': [],
};
```

Unsupported Bolt entries such as `@blocksize`, `@serialize`, and `@restore` are removed. Generic EEL2 / EEL_VM reports that no host-specific section contract is predefined.

The default contract remains:

- RootlessJamesDSP Modern
- Stereo
- 44.1 kHz and 48 kHz
- Zero latency
- Mobile-balanced CPU target
- Galaxy S10 and Galaxy S24 Ultra
- Parameter smoothing required
- Output protection required

Templates may override project preferences but may not add unsupported host capabilities.

## Prompt modes

### Architect

Requires plugin name, purpose, audible result, source material, and definition of success. Requests an implementation-ready architecture and forbids the final EEL2 script.

### Build

Requires plugin name, purpose, audible result, and approved architecture report. Requests exactly one complete EEL2 script plus a truthful validation report.

### Repair

Requires plugin name, current script, and defect description. Requests a complete corrected script, diagnosis, change summary, and verification limits.

### Refine

Requires plugin name, current script, and refinement goal. Requests a complete revised script while preserving unspecified accepted behavior.

### Optimize

Requires plugin name and current script. Optimization notes are optional. Requests measurable CPU, memory, or latency improvement without unauthorized sonic change.

### Review

Requires plugin name and a script. Requests findings and recommendations, not a rewritten script.

All modes use meaningful-content validation, ignore punctuation-only values, omit empty optional sections, include the selected runtime contract, and distinguish facts from assumptions.

## Workspace persistence

```ts
interface WorkspaceEnvelope {
  schemaVersion: 3;
  activeId: string | null;
  entries: ProjectEntry[];
}
```

Storage key: `eelforge.projects.v3`.

The active project ID is persisted. If it no longer exists, EELForge selects the first valid project or returns to the dashboard.

Writes are debounced and wrapped in error handling. A quota failure leaves the in-memory project usable, reports that browser storage is full, recommends export and version cleanup, and never claims the save succeeded.

## Migration

Accepted inputs:

- Schema-3 workspace envelope
- Bolt schema-3 entry array
- Raw schema-3 project
- Current schema-2 project
- Schema-1 Phase 1A project
- Export envelope containing `project`

Legacy storage keys:

```text
eelforge.project.v1
eelforge.project.v2
eelforge.project
eelforge.phase1a.project
```

Migration retains user text and supported contract values, supplies safe defaults for new fields, converts schema-1 `Untitled EEL Effect` to a blank name, skips malformed legacy entries without destroying valid entries, writes the schema-3 envelope after success, and leaves legacy keys untouched during v0.2 for recovery.

## Import and export

Export uses:

```json
{
  "schemaVersion": 3,
  "appVersion": "0.2.0",
  "exportedAt": "ISO-8601 timestamp",
  "project": {}
}
```

Import accepts the envelope and supported raw legacy projects only after structural validation. Arbitrary JSON such as `{}` is rejected.

Every imported project becomes a new entry with a new UUID and timestamps, migrated content, and no imported version snapshots. Import never silently replaces an existing project.

## Version history

Versions are created only through **Save Version**.

Each project retains at most 10 snapshots. The serialized workspace has a 3 MiB budget. When the budget is exceeded, oldest version snapshots are pruned across projects until it fits. Active project content is never truncated.

If the workspace still cannot be persisted, the save reports failure and recommends export. Success is shown only after storage succeeds.

Restoring a version preserves the active project's identity and creation timestamp while restoring its saved content.

## Interface behavior

The Bolt dashboard and workspace remain, including search, templates, project cards, mode tabs, readiness display, mode-specific fields, and version save/restore.

Deletion requires confirmation and identifies the project. Import, storage, clipboard, and download errors produce specific visible messages.

Onboarding appears after the first project is created and remains dismissed for that project after acknowledgment.

The placeholder Compare control is removed from v0.2.

## Templates

The four Bolt templates remain:

- Warm Saturator
- Transparent Limiter
- Stereo Widener
- Tape Character

Template content is starter text, not a validation claim. References are inspiration. Templates must not promise alias-free operation, true-peak compliance, or other measured results before implementation and testing.

## Verification

Unit coverage includes meaningful-content validation, filenames, every prompt mode, host contracts, schema-1/2/3 migration, strict import rejection, ID regeneration, reset identity, active-project persistence, version limits, storage pruning, and quota errors.

Interaction coverage includes dashboard lifecycle, first-project onboarding, mode switching, continuous typing without focus loss, readiness updates, import and clipboard errors, and version restoration.

Required commands:

```bash
npm ci
npm run typecheck
npm test
npm run build
npm run build:single
npm run verify:single
```

CI runs type-check, tests, and production build. The portable verifier confirms no unresolved script, stylesheet, asset, network, dynamic-import, or service-worker dependencies.
