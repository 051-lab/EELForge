# Phase 2A — Architect Handoff

## Goal

Convert a plugin vision and implementation contract into a clear, concise, implementation-ready architecture request for an AI agent.

## Essential context

A project is ready for Architect mode when these five fields contain meaningful text:

1. Plugin name
2. Plugin purpose
3. Desired audible result
4. Source material
5. Definition of success

Punctuation-only placeholders are ignored.

## Advanced sonic context

Optional fields include:

- Preserve
- Avoid
- Intended use or insertion point
- Preferred controls
- References or inspiration

Empty optional fields are excluded from the final handoff.

## Runtime contract

The handoff includes:

- Host profile
- Available execution sections
- Channel mode
- Sample rates
- Latency mode
- CPU target
- Device targets
- Parameter smoothing policy
- Output protection policy
- Additional constraints

## Architect return contract

Architect mode requests design, not production code. The agent must end with a Recommended Build Specification that can be passed to the next development stage.
